# Claude Code Project Guidelines & Agent Orchestration

## 1. Subagent & Model Routing Rules
Whenever launching background processes, subagents, or tool executions, you MUST enforce the following model tiering:

- **Tier 1: Grunt & Discovery (Model: haiku)**
  - Use cases: All codebase searches, grep, mapping file trees, finding call sites, reading terminal outputs, and running test suites.
  - Constraint: Read-only operations. Do not allocate high-reasoning tokens to log scanning or repository traversal.

- **Tier 2: Primary Implementation (Model: sonnet)**
  - Use cases: Writing business logic, implementing features, refactoring, and following TDD micro-tasks.
  - Constraint: Default model for standard execution.

- **Tier 3: Gatekeeper & Architecture Review (Model: opus)**
  - Use cases: Only activated on three strict checkpoints:
    1. Architectural Sign-off: Before locking the implementation plan generated by writing-plans.
    2. Stuck Loop Prevention: Immediately when the same error occurs twice consecutively during execution.
    3. Final Quality Gate: During requesting-code-review / finishing-a-development-branch before anything is declared complete or committed.
  - Constraint: Opus never writes boilerplate or searches files; it only outputs explicit approval (APPROVE) or rejection with root-cause feedback (REJECT: reason).
